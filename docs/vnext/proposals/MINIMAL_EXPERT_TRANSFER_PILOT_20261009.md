# MINH TRÍ — Minimal expert-transfer feasibility pilot (proposal only)

Date 2026-10-09. Status: DRAFT / NOT RUN / NOT EVIDENCE OF EXPERTISE.
Protected main: a5ed9d8347a60b95503fe2e5de6b95fd8375eb76.
Keep Foundation V1, Master Blueprint V1, one GitHub authority, Fast Lane and existing roles. No new architecture, runtime, schema, law, active task or autonomous curriculum. This is a plan, not permission to alter production state.

OBJECTIVE. Determine whether a MINH TRÍ study/reasoning method provides value beyond giving the same frozen source packet to the same underlying model. Primary result concerns only one Owner-selected bounded task family, never global intelligence.

PREREQUISITES.
1. Owner selects a specific topic/domain and a trusted task and answer-key custodian external to the solver; if no such keeper or secure non-solver storage is available, BLOCKED. Separate task author, gold author, solver and blind judge; identity declaration alone is not independence proof.
2. New task and answer keys must never enter a public repo, solver retrieval, shared chat context or producer prompt before scoring. Existing public-gold retrieval fixtures are contaminated for this purpose. Use an auditable private custody process and, if a public commitment is wanted, avoid easily brute-forced hashes of small gold strings; consider a secret-key HMAC retained by the keeper.
3. Pre-register exact model build, allowed tools, source packet/version and primary endpoint, scoring, serious-error constraint, N, budget, stop rule, withdrawal/contamination policy before generating outputs. Five tasks are an inexpensive feasibility screen, never enough for broad superiority claims. If owners require confirmatory claims, separately justify larger N/power.
4. A1: same model with the exact source snapshot and budget, but without MINH TRÍ structured study instructions/learned records. A2: same model, same source opportunity, same budget, with only the proposed study method and already accepted knowledge representations. Any difference must be logged. Do not credit mere longer prompt or hidden extra retrieved data as a learning gain.
5. Inputs are pre-sealed externally; arm order randomized; independent execution contexts; both answers retained as outputs before judging. Blinded judge applies the frozen primary metric. If a scenario leaks to the solver, the task becomes ineligible before unblinding.
6. Store only safe metadata/commitments and a PENDING_REVIEW receipt in GitHub candidate: task IDs, model/build, source commit, method versions, budgets, primary score breakdown, sealed-key verifier attestation, caveats, costs and serious errors. No raw gold, sensitive private case or unredacted business data.
7. A separate reviewer checks no leakage, independent keeper attestation, fairness, score and negative cases. Protected acceptance is required before any official claim. Fresh chat reads accepted outcomes from protected main, not from critic chat alone.

STOP/GO:
- If no independent custody, true unseen task generation or fair resource control, mark BLOCKED and return to ordinary Owner-directed learning; do not invent scores.
- If feasibility screen fails or shows no advantage, record NULL/FAIL and stop expansion rather than redesign architecture by assumption.
- If feasibility looks useful, only recommend a separate confirmatory experiment with pre-agreed sample/power and cost; do not declare MINH TRÍ expert or open Foundation.
- The Original EIA-V2 PR #344 remains the frozen Claude critique target. This pilot proposal is independent and not yet accepted.

RISK REMAINING: Even independent tests cannot by themselves prove model weight adaptation; gains may derive from scaffolding, retrieval and prompt method. Claims must specify the tested configuration and comparison.
