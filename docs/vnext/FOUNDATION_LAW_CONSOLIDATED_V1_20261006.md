# MINH TRÍ — FOUNDATION LAW CONSOLIDATED v1 — 2026-10-06

**Status:** CURRENT CONSOLIDATED LAW ROUTER / PRESERVES SOURCE LAW HISTORY

## Purpose

Provide one compact normative route after Foundation Closure without rewriting or deleting the underlying Owner laws.

## Precedence

1. Current explicit Owner instruction / constitution-level decision.
2. Stable Owner law.
3. Policy.
4. Domain rule.
5. ADR / bounded operational decision.
6. Current state and task registry as operational truth, not law.
7. Historical/candidate records as evidence/provenance only.
8. Chat memory is non-canonical.

Same-level conflict requires explicit supersession or a bounded conflict-resolution task. Missing/conflicting authority fails closed for the affected mutation.

## Durable authority

- Protected GitHub main is the durable continuity authority.
- `state/bootstrap.json` is the single vNext boot root.
- `state/current.yaml` holds mutable current-state facts.
- `state/tasks.yaml` is the single canonical task registry.
- Material state may not exist only in chat.

## Learning law

- Owner chooses what to learn.
- Material learning must be durably recorded.
- Knowledge records preserve provenance, evidence/status, supersession lineage, semantic dependencies, and domain rules.
- Ordinary learning may use Knowledge Fast Lane v1, but protected-main review remains required.
- PENDING_REVIEW / SUPERSEDED / REFUTED / DISPUTED material is not silently treated as established support when freshness is required.
- No automatic VERIFIED.

## Capability discipline

Implementation, CI, retrieval, or a fixture PASS proves only the bounded claim recorded by its evidence.
Autonomous learning runtime, automatic self-critique runtime, and meta-learning runtime remain OFF unless a later explicit Owner decision and proof changes that truth.

## Architecture budget

Knowledge growth must not force architecture growth.
No new architecture layer solely because the knowledge corpus becomes larger.

Foundation architecture may reopen only when:
- measured evidence/test failure exposes a foundation defect;
- real operation exposes a foundation defect not covered by current mechanisms; or
- Owner explicitly changes a foundation objective.
