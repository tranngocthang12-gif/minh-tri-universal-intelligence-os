# 0. WHY THIS RESTORATION EXISTS

The first MINH TRÍ implementation correctly created an offline evidence/prediction/critique core, then AI Commons, GitHub Brain pinning, Project Law and Bootstrap candidates.

A historical Owner dialogue supplied in the current working session shows that the original design target was broader than the v0.1 code:

- a universal Tier 1 that learns how to learn any domain;
- a learning-maturity path from memory through transfer;
- explicit understanding, prediction, falsification and self-repair;
- skill distillation and skill testing;
- provider-neutral AI selection by demonstrated capability;
- reverse planning from the desired end-state;
- highest-leverage bottleneck selection;
- a later Tier 3 Execution/Factory layer.

The historical dialogue is **source evidence for Owner intent**, not executable project law. Its raw contents are not stored in this public repository.

This v0.2 candidate reconstructs the missing universal mechanisms while preserving current safety/authority boundaries.

# 1. DESIGN THESIS

MINH TRÍ is not an AI model.

MINH TRÍ is an **organization-level intelligence system** whose durable brain is versioned on GitHub and whose reasoning capacity may be supplied by replaceable human or AI cognitive providers.

The target capability is:

```text
REMEMBER
→ KNOW
→ UNDERSTAND
→ PREDICT
→ ACT SAFELY
→ VALIDATE
→ CRITICIZE ITSELF
→ IMPROVE HOW IT LEARNS
→ REPAIR ITS METHODS
→ TRANSFER THE LEARNING METHOD
```

“Superhuman/superior intelligence” is an **aspirational design target**, not a current empirical claim.

# 3. TIER 1 — RESTORED UNIVERSAL COMPONENTS

## 3.1 Reality & Problem Framing

Before solution selection:

```text
CURRENT REALITY
→ undesired state
→ known / unknown
→ constraints
→ risk
→ consequences
→ conditions / causes / triggers / maintainers / amplifiers / feedback loops
→ desired state
```

Do not infer causality from correlation.

The Four Noble Truths may inspire the **modern structure** “reality → conditions → right target → path”, but real-world causal claims must use the relevant domain causal model.

## 3.2 Goal Decomposition & Bottleneck Governor

Owner goals must not jump directly to actions.

```text
OWNER PURPOSE
→ TARGET STATE
→ SUCCESS CONDITIONS
→ DEPENDENCY / CAPABILITY GRAPH
→ CURRENT GAPS
→ MATERIAL UNKNOWNS
→ HIGHEST-LEVERAGE BOTTLENECK
→ LEARNING OR ACTION UNIT
```

The system should work backward from the desired end-state.

Priority must consider, without pretending uncalibrated precision:

- expected decision improvement;
- expected information gain;
- business/user value;
- capability transfer value;
- cost;
- time;
- risk;
- reversibility/irreversibility;
- dependency criticality.

Until calibrated by real outcomes, this is a **decision rubric**, not a fake numeric truth score.

If no eligible high-value unit exists: `WAIT`.

## 3.3 Epistemic State & Knowledge Lifecycle

The brain must explicitly know:

- facts/observations;
- inferences;
- hypotheses;
- predictions;
- opinions;
- unknowns;
- open counterevidence;
- active experiments;
- decisions waiting;
- knowledge expiry/staleness;
- strategy regression/decay;
- provider error patterns;
- skill maturity.

Minimum material labels remain bounded; domain-specific labels may extend only in Tier 2.

Knowledge must be reopenable on:

`NEW_EVIDENCE | STALENESS | REGRESSION | OWNER_REOPEN | DEPENDENCY_CHANGE | POLICY_CHANGE | ENVIRONMENT_CHANGE`.

## 3.4 Understanding Gate

Reading is not understanding.

Source-derived practical understanding signals:

1. explain in one's own words;
2. distinguish from a nearby concept;
3. predict what should happen if applied;
4. state conditions/evidence that would falsify it.

**Restoration proposal:** for cheap/reversible learning work, at least one understanding signal plus a falsifier may be sufficient to justify a small test. For material decisions, prediction + falsifier + relevant evidence are required. This risk-tiered rule is a MINH TRÍ design proposal and must be tested; it is not yet implemented.

## 3.5 Hypothesis / Falsification

Every material hypothesis needs:

- claim;
- alternative explanations;
- evidence for;
- evidence against;
- assumptions;
- falsifier;
- discriminating test;
- scope.

A hypothesis that cannot lose is not useful for learning.

## 3.6 Prediction / Experiment / Resolution

Before outcome visibility:

- preregister prediction/range where measurable;
- define metric;
- define pass/fail/underpowered semantics;
- define minimum useful effect or decision threshold;
- define stop rule;
- define cost/timebox;
- freeze.

After outcome:

```text
PREDICTION
→ OBSERVED OUTCOME
→ ERROR / CALIBRATION
→ ATTRIBUTION STATUS
→ LESSON CANDIDATE
```

Do not turn `UNDERPOWERED` into `FAIL`.

## 3.7 Critique / Adjudication

Three logical seats remain universal:

- proposer/learner;
- critic;
- adjudicator.

Material tasks should prefer blind independent work before reveal when information value justifies the cost.

No voting truth.

```text
CLAIM
→ EVIDENCE
→ COUNTEREVIDENCE
→ DISCRIMINATING TEST
→ HOLD / REVISE / CANDIDATE
```

## 3.8 Learning Maturity L0–L9

This restores the original capability ladder as a **maturity model**, not a mandatory claim state machine.

| Level | Meaning | Minimum evidence |
| --- | --- | --- |
| L0 MEMORY | remember what happened | durable event/reference |
| L1 KNOWLEDGE | know a fact/rule | source/evidence + scope |
| L2 UNDERSTANDING | explain why/when; distinguish; falsify | understanding gate |
| L3 PREDICTION | predict before answer/outcome | preregistered prediction |
| L4 ACTION | use understanding in a bounded action/test | authorized controlled action |
| L5 VALIDATION | reality tests the understanding | observed outcome + data quality |
| L6 SELF-CRITICISM | actively seek own failure | independent critique/counterevidence |
| L7 META-LEARNING | compare learning methods | method/baseline scorecard |
| L8 SELF-REPAIR | repair workflow/skill/method | sandbox test + validation + rollback |
| L9 TRANSFER | transfer learning method across domains | cross-domain test without domain leakage |

Not every knowledge item must reach L9. A maturity claim is valid only for the stated scope.

## 3.9 Lesson → Skill Lifecycle

Learning must not stop at prose lessons.

Target lifecycle:

```text
RESOLVED OUTCOME
→ SCOPED LESSON
→ SKILL / PROCEDURE CANDIDATE
→ BENCHMARK
→ TRIAL
→ ACTIVE / REJECTED / RETIRED
→ REGRESSION WATCH
→ ROLLBACK / RELEARN
```

A skill stores:

- version;
- objective;
- scope;
- prerequisites;
- procedure;
- evidence basis;
- benchmark;
- known failure modes;
- cost profile;
- rollback version;
- expiry/retest trigger.

**Activation gate:** skill promotion remains disabled until the benchmark contract and minimum evidence are defined and tested. One success cannot promote a skill.

## 3.10 Meta-Learning

The system must ask:

> Which learning method makes decisions more accurate, faster, cheaper, safer and more transferable?

Compare:

- procedure A vs B;
- single-provider vs multi-provider;
- research-first vs cheap-test-first;
- different experiment designs;
- different critique protocols.

Metrics may include:

- prediction error/calibration;
- decision quality proxy;
- severe error rate;
- time;
- monetary/tool cost;
- human correction;
- information gained;
- transfer success.

Do not optimize one metric in isolation.

## 3.11 Self-Repair

Restored core sequence:

```text
DETECT
→ DIAGNOSE
→ PROPOSE REPAIR
→ SANDBOX
→ TEST
→ VALIDATE
→ VERSION
→ REPLACE / ROLLBACK
```

May repair, within authority:

- workflow;
- skill/procedure;
- prompt;
- tool routing;
- provider selection;
- experiment design;
- non-authority architecture implementation details.

May **not** autonomously change:

- Owner mission;
- Project Law;
- major risk tolerance;
- spending/trading/publishing authority;
- Dhamma meaning boundary;
- canonical governance beyond delegated scope.

Core-law repair must be a reviewed `LAW_CHANGE_PROPOSAL`.

## 3.12 Provider Intelligence

AI providers are replaceable workers, not the brain.

Provider registry should eventually track per model/version/task class:

- capability;
- provider family;
- benchmark results;
- prediction/calibration performance where applicable;
- critique defect discovery rate;
- severe error profile;
- cost/tokens;
- latency;
- reliability/timeout rate;
- context/tool limits;
- provenance/identity status.

Routing:

```text
TASK REQUIREMENTS
→ ELIGIBLE PROVIDERS
→ EVIDENCE-BASED ROUTING
→ RESULT
→ SCORECARD UPDATE
```

### Champion/Challenger rule

The architecture may support `CHAMPION / CHALLENGER`, but promotion is **OFF by default** until sufficient real repeated outcomes exist.

This preserves the useful pattern from YouTube Business OS while respecting the explicit “not enough data yet” decision in `nao-nha-may`.

No model is a permanent champion.

# 5. TIER 3 — EXECUTION / FACTORY

Tier 3 converts validated understanding into bounded real action.

Examples:

- create artifact;
- call read-only analytics adapter;
- publish content;
- place a trade/order;
- spend budget;
- modify external systems.

Current authority:

`PUBLISH / TRADE / SPEND / IRREVERSIBLE ACTION = CLOSED`.

Future action requires:

- explicit capability;
- verified identity;
- Owner authorization where required;
- data/rights checks;
- risk limits;
- dry-run/sandbox where possible;
- rollback;
- audit event;
- post-action measurement.

Tier 1 deciding “this is worth testing” does not mean Tier 3 is authorized to execute it.

Accepted work must not be replayed merely because a new chat starts.

- task_id;
- brain pin;
- exact checkpoint;

- next exact action;
- blockers;
- role/lease;

# 7. AI COMMONS — COGNITIVE SYNERGY

AI Commons is not “four votes”.

For a material task, one target pattern is:

```text
FREEZE TASK / EVIDENCE
        ↓
BLIND INDEPENDENT ROUND
        ↓
REVEAL
        ↓
CROSS-CRITIQUE
        ↓
COUNTEREVIDENCE
        ↓
DISCRIMINATING TEST
        ↓
ADJUDICATION
        ↓
HOLD / REVISE / OWNER CANDIDATE
```

Number of participants is dynamic.

Use one provider for simple work when additional providers do not justify cost. Use more when uncertainty, risk or expected information value warrants it.

Benchmark must compare AI Commons against simpler baselines before claiming “synergy”.

# 8. MONEY-MAKING GUIDANCE & DHAMMA BOUNDARY

Owner's direction: money-making should be guided by a modern application lens inspired by the Four Noble Truths and Noble Eightfold Path.

Operational values include:

- see reality accurately;
- do not let greed/fear/FOMO distort analysis;
- do not deceive;
- examine the mechanism that produces money;
- avoid unnecessary harm;
- act proportionally to evidence;
- prefer small/reversible tests under uncertainty;
- monitor the system's actual state;
- concentrate effort on the highest-leverage bottleneck.

Boundary:

- this is `MODERN_INTERPRETATION / MODERN_MODEL`;
- real finance/media/business causality requires domain models and evidence;
- business profit does not prove Buddhist doctrine;
- canonical doctrinal meaning must be source-verified separately.
