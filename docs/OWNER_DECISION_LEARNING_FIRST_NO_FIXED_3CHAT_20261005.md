# OWNER DECISION — LEARNING-FIRST / NO FIXED 3-CHAT DISPATCH — 2026-10-05

Status: OWNER DECISION / CANDIDATE UNTIL PROTECTED MERGE

## 1. Core direction

MINH TRÍ is being built first as a deep-learning intelligence system.

Current priority is not broad real-world execution.

Current priority is to:
- learn a very large body of knowledge;
- learn deeply, not superficially;
- become highly competent across important domains;
- study real success, failure, mixed outcomes and market behavior;
- understand mechanisms, context, transfer limits and counterexamples;
- accumulate durable knowledge before later practical execution.

The intended analogy is human development:
learn broadly -> understand deeply -> build judgment -> only after sufficient knowledge, move into sustained real-world practice.

## 2. Current learning material

Until the Owner explicitly moves a domain into practical execution, external market experience is primary learning material.

This includes:
- successful cases;
- failed cases;
- mixed cases;
- postmortems;
- market outcomes;
- operating patterns;
- strategic mistakes;
- execution failures;
- customer/audience response where evidence exists.

External cases remain learning capital and must preserve provenance, context, uncertainty and transfer limits.

Learning from external success/failure does NOT mean:
- copying a case blindly;
- treating popularity as proof;
- treating one success as a causal law;
- treating external experience as already verified for Owner context.

## 3. Practical execution timing

Sustained practical execution comes later, after enough knowledge and judgment have accumulated, unless the Owner explicitly orders an immediate practical action.

No automatic threshold for "enough knowledge" is defined by the system.

The Owner decides when a domain is ready to move from learning-first into practical execution.

## 4. Orchestrator role after this decision

The role ĐIỀU HÀNH remains.

Its primary functions are now:
- recover the whole project state;
- challenge assumptions;
- critique important conclusions;
- compare competing explanations;
- detect overclaim and missing evidence;
- synthesize what has been learned;
- identify knowledge gaps;
- maintain continuity and learning direction;
- advise the Owner.

ĐIỀU HÀNH is not required to maintain or dispatch a fixed pool of three worker chats.

## 5. Fixed 3-chat dispatch is removed

The previous operating idea of three standing worker chats / three fixed simultaneous assignments is superseded.

There is no canonical requirement for:
- exactly three worker chats;
- QUÂN-1 / QUÂN-2 / QUÂN-3 capacity;
- automatic refill of three slots;
- three simultaneous learning lanes;
- permanent MAIN / EARLY_TEXT_AUDIT / CRITIC roles as a fixed workforce.

Additional chats may still be used ad hoc when useful for:
- independent criticism;
- source checking;
- comparison;
- bounded specialist review.

Such chats are temporary seats, not a standing three-chat workforce.

## 6. Learning-first operating loop

Current preferred loop:

OWNER LEARNING GOAL
-> SOURCE / MARKET SUCCESS-FAILURE CASES
-> PROVENANCE
-> DEEP STUDY
-> COMPARE / COUNTEREXAMPLE
-> ĐIỀU HÀNH CRITIQUE
-> SYNTHESIS
-> DURABLE KNOWLEDGE
-> REVISIT / CORRECT / DEEPEN

Later, when the Owner decides a domain is mature enough:

DURABLE KNOWLEDGE
-> PRACTICAL PLAN
-> REAL EXECUTION
-> FIRST-PARTY OUTCOME
-> SUCCESS / FAILURE ANALYSIS
-> LESSON UPDATE

## 7. Self-learning boundary

This decision does not upgrade the current self-learning classification.

Current system remains:
PROPOSAL_GOVERNANCE_PIPELINE_NOT_AUTONOMOUS_BEHAVIOR_ADAPTATION

External market cases are useful learning capital, not automatic evidence of behavioral self-learning.

A future claim that MINH TRÍ has learned from its own experience still requires a clean closed empirical loop.

## 8. Existing safety/evidence laws remain

This decision does not weaken:
- GitHub-first durable memory;
- recorded != VERIFIED;
- source provenance;
- counterevidence;
- fresh-read requirements;
- protected branch / PR / CI / merge governance;
- no automatic VERIFIED;
- no silent canonical mutation.

## 9. Superseded coordination artifacts

The following coordination concepts are superseded only insofar as they require a fixed multi-chat workforce:
- fixed 3-chat Buddhist parallel plan;
- fixed worker-slot dispatch/refill;
- three-chat capacity as an operating target.

Their source/audit/critique ideas may still be reused as methods without preserving the three-chat staffing model.
