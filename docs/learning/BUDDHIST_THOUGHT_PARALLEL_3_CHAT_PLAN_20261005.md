## Merge / handoff protocol

1. CHAT 2 or CHAT 3 completes one bounded packet.
2. It records the packet durably on its own branch/PR.
3. CHAT 1 fresh-reads that packet.
4. CHAT 1 decides:
   - ACCEPT
   - ACCEPT_WITH_CORRECTION
   - DEFER_OPEN_AUDIT
   - REJECT_WITH_REASON
5. Only CHAT 1 incorporates accepted findings into numbered checkpoints and routing state.
6. No claim becomes VERIFIED merely because another chat wrote it.

## Collision prevention

Never allow:
- two chats editing PROJECT_STATE Buddhist current/next simultaneously;
- two chats independently declaring the same A checkpoint completed;
- a support chat rebasing the canonical learning route around its own findings;
- hidden deletion of an open audit because one seat failed to find evidence.

If a support chat finds a contradiction with the current canonical branch:
- stop only the affected claim;
- record the contradiction;
- continue independent audit work;
- do not rewrite canonical state from the support seat.
